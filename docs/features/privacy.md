# 数据与隐私

Pilot 在设备上管理会话和用户配置，并连接你选择的模型与工具服务。使用前应明确资料将交给哪些服务，以及企业空间的管理范围。

## 设备上的数据

个人会话、助手设置和自有 Provider 配置保存在应用私有存储。个人使用无需企业账号；企业接入使用组织身份和会话凭据，受该空间的授权与发布配置约束。

## 哪些操作会联网

| 操作 | 资料去向 |
| --- | --- |
| 模型对话、图片生成、附件识别与远程语音 | 相应配置的模型或语音服务 |
| 搜索、MCP、Runcove 等工具调用 | 该工具服务及工具实际访问的目标 |
| 企业接入、配置、用量与工作区 | 所连接的 Orchelm 平台及获准资源 |
| WebDAV / S3 备份与文件传输 | 用户或组织配置的存储服务 |
| 更新检查及下载 | 官方版本端点与 GitHub Release 下载地址 |

传给模型的文本、附件和工具结果会参与相应服务的处理；具体保留策略由服务提供方或组织管理。应用私有存储不等于资料永远不离开设备。

## 工具与文件授权

工具可以按配置要求人工确认。个人与企业历史、记忆、文件访问保留原空间身份；切域、撤权或退出后，旧操作不能自动取得新空间的权限。缓存中的结果也不能代替当前访问资格。

本地 Workspace 使用 PRoot 提供 Linux 文件与执行环境。它不是恶意程序的内核安全边界；只执行自己信任的工具与程序，并按需要配置权限。

## 备份与退出

个人备份导出个人数据及所需共享资源，恢复时保留企业数据边界。退出企业空间可按界面选择保留历史；卸载应用会删除应用私有数据，不会自动删除远端文件、已导出文件或外部备份。

## 凭据与诊断

设置页对部分敏感字段提供遮罩，诊断脱敏凭据；复制日志、分享图片或导出文件前仍应检查内容。API Key 会用于相应服务的认证，不应把“保存在设备”理解为“不会发送给服务”。

源代码和当前数据契约见 [公开仓库](https://github.com/topabomb/rikkahub_mcp) 与 [数据持久化参考](https://github.com/topabomb/rikkahub_mcp/blob/master/docs/references/data-persistence.md)。
